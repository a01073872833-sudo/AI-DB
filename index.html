# 목적 - 입력된 자료를 기반으로 미니멀리즘 스타일의 대시보드형 웹페이지를 제작한다. - 핵심 정보와 데이터를 사용자가 빠르게 파악할 수 있도록 정보 위계와 시각적 구조를 설계한다. - 최종 결과물은 브라우저에서 바로 실행 가능한 HTML 형식으로 제작한다. # 역할 - 숙련된 웹 기획자, UI/UX 디자이너, 프론트엔드 개발자처럼 행동한다. - 정보 구조, 사용자 경험, 데이터 시각화, 반응형 디자인을 종합적으로 고려한다. # 입력문 - 웹페이지 주제: [주제 입력] - 웹페이지 목적: [목적 입력] - 주요 사용자: [사용자 입력] - 활용 데이터 및 콘텐츠: [자료 입력] - 메인 색상: [메인 색상 입력] # 디자인 기준 - 대한민국 디지털 정부서비스 디자인 원칙인 KRDS를 디자인 참고 기준으로 활용한다. - KRDS의 정보 전달 중심 구조, 명확한 시각적 위계, 일관성, 접근성, 사용성을 고려한다. - KRDS를 그대로 복제하지 않고 웹페이지의 목적과 콘텐츠에 맞게 적용한다. # 디자인 스타일 - 미니멀리즘 스타일 - 대시보드형 레이아웃 - 불필요한 장식 요소 최소화 - 충분한 여백 사용 - 명확한 콘텐츠 그룹화 - 카드 기반 정보 구조 활용 - 전체적으로 정돈되고 전문적인 느낌 유지 - 한 화면에서 너무 많은 정보를 노출하지 않는다. # 색상 - 메인 색상: [메인 색상 입력] - 메인 색상을 강조 요소, 버튼, 핵심 데이터에 제한적으로 사용한다. - 배경은 White 또는 밝은 Neutral 계열을 기본으로 사용한다. - 보조 색상은 메인 색상과 조화되는 Neutral 계열을 활용한다. - 상태값이 필요한 경우 성공, 주의, 오류 정보를 시각적으로 구분한다. - 지나치게 많은 색상 사용을 금지한다. # 레이아웃 전체 페이지는 다음 구조를 기본으로 구성한다. 1. Header - 페이지 또는 서비스명 - 주요 메뉴 - 필요한 경우 사용자 정보 또는 기능 버튼 2. Sidebar 또는 상단 Navigation - 주요 카테고리 - 현재 선택된 메뉴를 명확하게 표시 - 모바일에서는 접을 수 있는 구조 적용 3. Dashboard Summary - 핵심 지표를 카드 형태로 제공 - 핵심 수치 - 간단한 설명 - 증감 또는 상태 정보 4. Main Data Visualization - 핵심 데이터를 차트 또는 그래프로 표현 - 데이터 특성에 적합한 시각화 유형을 선택 - 제목, 범례, 단위 등을 명확하게 표시 5. Detail Information - 세부 데이터 - 카테고리별 분석 내용 - 비교 정보 - 필요할 경우 표 또는 카드 사용 6. Footer - 출처 - 저작권 - 추가 정보 # 대시보드 카드 디자인 - 동일한 radius와 spacing 규칙을 적용한다. - 카드 내부에는 제목, 핵심 수치, 보조 설명 순으로 정보 위계를 구성한다. - 지나친 그림자 사용을 피한다. - 테두리 또는 미세한 명암 차이를 활용해 영역을 구분한다. # 데이터 시각화 - 입력된 데이터에 가장 적절한 차트 유형을 선택한다. - 단순 장식 목적으로 차트를 사용하지 않는다. - 데이터 비교가 중요할 경우 비교 관계가 명확하게 보이도록 구성한다. - 숫자 단위와 기간을 명확하게 표시한다. - 차트 색상은 전체 디자인 시스템과 통일한다. - 입력된 자료에 없는 수치나 데이터를 임의로 생성하지 않는다. # 타이포그래피 - 한글 가독성이 높은 Sans-serif 계열 폰트를 사용한다. - 제목, 부제목, 본문, 보조 텍스트의 크기를 명확하게 구분한다. - 지나치게 작은 폰트 사용을 피한다. - 핵심 수치에는 본문보다 큰 글자 크기를 적용한다. - 폰트 굵기만 과도하게 사용하지 않는다. # UI/UX - 사용자가 페이지 진입 후 핵심 정보를 빠르게 이해할 수 있어야 한다. - 중요한 정보부터 위쪽에 배치한다. - 클릭 가능한 요소는 명확하게 구분한다. - 버튼과 메뉴에는 hover 및 focus 상태를 제공한다. - 과도한 애니메이션은 사용하지 않는다. - 필요한 경우 자연스러운 transition만 사용한다. # 접근성 - 텍스트와 배경의 대비를 충분히 확보한다. - 키보드만으로 주요 기능을 사용할 수 있도록 고려한다. - 의미 있는 이미지에는 alt 속성을 적용한다. - 아이콘만 사용하는 경우 의미를 확인할 수 있는 텍스트 또는 aria-label을 추가한다. - 상태를 색상만으로 구분하지 않는다. # 반응형 디자인 다음 환경에서 정상적으로 사용할 수 있도록 제작한다. - Desktop - Tablet - Mobile 반응형 전환 시 다음 항목을 확인한다. - 카드 재배치 - Navigation 축소 - 차트 크기 자동 조정 - 표의 가로 스크롤 - 버튼 및 터치 영역 - 텍스트 줄바꿈 - 요소 겹침 및 잘림 # HTML 제작 기준 - HTML5 표준을 준수한다. - 시맨틱 태그를 적극적으로 사용한다. - header, nav, main, section, article, footer 구조를 명확하게 구분한다. - CSS와 JavaScript가 필요한 경우 HTML 내부에 포함하여 단일 HTML 파일만으로 실행 가능하도록 제작한다. - 외부 라이브러리는 꼭 필요한 경우에만 사용한다. - 코드 중복을 최소화한다. - 클래스 이름은 기능과 구조를 이해할 수 있도록 작성한다. # 파일 구조 최종 결과물은 기본적으로 다음 형식을 따른다. index.html HTML 내부 구성:
# 금지사항 - 입력 자료에 없는 데이터를 임의 생성하지 않는다. - 과도한 그라데이션 사용 금지 - 과도한 그림자 사용 금지 - 과도한 애니메이션 사용 금지 - 불필요한 장식 이미지 사용 금지 - 한 화면에 너무 많은 카드 배치 금지 - 동일한 정보를 반복해서 표현하지 않는다. - 의미 없는 Lorem Ipsum 텍스트를 사용하지 않는다. # 최종 검수 웹페이지 제작 완료 후 다음 항목을 확인하고 문제가 있으면 수정한 뒤 최종 결과물을 출력한다. 1. HTML이 정상적으로 실행되는가? 2. 레이아웃이 깨지는 구간이 없는가? 3. 텍스트와 UI 요소가 겹치지 않는가? 4. 모바일에서도 정상적으로 표시되는가? 5. 모든 데이터가 입력 자료와 일치하는가? 6. 대시보드의 핵심 지표가 쉽게 파악되는가? 7. KRDS 기반의 정보 전달 및 접근성 원칙이 반영되어 있는가? 8. 색상, 카드, 폰트, 여백이 일관적인가? 9. 불필요한 코드 또는 요소가 포함되어 있지 않은가? # 출력 형식 - 설명을 길게 작성하지 말고 완성된 결과물을 중심으로 출력한다. - 최종 결과는 실행 가능한 `index.html` 코드로 제공한다. - HTML, CSS, JavaScript가 필요한 경우 하나의 HTML 파일 내부에 통합한다. - 코드 작성 후 자체 검수를 진행하고 오류가 수정된 최종본만 출력한다.
